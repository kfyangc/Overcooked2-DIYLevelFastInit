# DIYLevelFastInit

《Overcooked! 2》[OC2DIYLevel](https://github.com/gua248/Overcooked2-LevelEditor) 的启动与内存优化补丁。需要 BepInEx 5 和 OC2DIYLevel 0.10.0 或 0.11.0。

[English README](README.md)

## 测试版 1.7.0.7：启动目录调度与耗时定位

保留 0.10／0.11 双版本兼容。缓存命中的地图包改为按约 4 ms 的工作预算批量处理，不再每包固定等待一帧；预算在包之间检查，单包读取或对象创建仍可能超过预算。目录顺序、完整关卡信息和 SO 身份保持不变。公共资源逐个加载前重新检查当前驻留列表，跳过等待期间被其他插件加载完成的包。冷扫描仍逐包读取并等待安全回收，不并行预加载 info 图。

日志新增 `startup synchronous common setup`、每文件的 `info bundle preparation timing`、`common bundle timing`、`catalog timing` 和总计 `startup timing`。总计区分 info 文件准备、公共资源、目录缓存读取、轻量对象创建、冷扫描包／资源加载、元数据提取写盘、回收等待、快照、菜单、主动暂停和批处理等待帧；缓存未命中会说明文件缺失、info 长度／时间变化或缓存损坏等原因。`bundleMs` 包含依赖图解析和原生容器等待，`extractWriteMs` 包含冷扫描轻量对象创建与缓存写盘，字段不是 CPU 时间；各阶段是包含关系，不能把总计与子项重复相加。缩略图另记录 `thumbnail source warmup timing` 与包含暂停的整体预热耗时。

反馈“进入游戏后加载很久”时，保留从 `LoadHeavy started` 到 `startup timing` 的日志及之后的缩略图预热记录，即可区分目录缓存、公共资源和源图预热。此版不承诺把一分钟降到某个固定值，实际 Unity 读取、对象创建、菜单及联机仍需游戏内复测。离线记录和测试 DLL 位于 `../.verification/startup-1.7.0.7/`。

## 测试版 1.7.0.6

同一个 DLL 兼容 OC2DIYLevel 0.10.0 和 0.11.0。0.10 保留旧的可选菜谱工厂补丁；0.11 的旧工厂已删除，改为检测并挂钩 `CustomRecipeOptionalRegister.GetOrderDefinitionNode`。继续跟踪自定义菜谱节点、两个模型映射工厂和克隆的预制体；同一结果经过多个入口时由原有所有权集合去重。其他必需补丁仍严格检查，启动日志记录实际选择的可选菜谱入口。

此测试版从 1.7.0 修改，仅包含双版本菜谱补丁兼容，不包含独立分支中的进图等待或菜谱缓存实验。原生资源生命周期和实际联机仍需游戏内验证。

两个目标版本均通过离线检查：Release 构建、每版 31 个 Harmony 签名、13 个反射成员和 96 项前端断言，以及目录／缩略图、选档状态和网络消息检查。生产菜谱安装函数选中了对应版本的四个目标；检查时在 Harmony 边界将依赖 Unity 的工厂方法体替换为签名相同的空实现。记录和测试 DLL 位于 `../.verification/compat-1.7.0.6/`，未执行 Unity 原生加载或 Steam 实际联机。

## 1.7.0

单机／房主与远端客机改为异步准备入关资源，地址有效时直接加载选中的 `LevelInfoSO`，只生成该关卡的配置。保留完整轻量目录、跨关卡集 info 依赖和七池运行库的资源所有权。确认存档后选档框保持可见并锁住输入，直到切图；取消或被替换的请求不会继续加载旧关卡，也不会解锁新的选档框。

每次启动将兼容的原始 `info*` 包校验后原地转换为独立 LZ4，保留原件和受哈希保护的恢复记录，所有加载器直接读取原地图路径。已经优化的包直接跳过，首次转换会增加启动等待。下方的配置与恢复方式同样适用于 1.7.0。缩略图预热以 StageThumbnailPreview 适配补丁安装成功为前提，按类型／方法检测，不依赖 DLL 文件名，也不读取对方自身的启用开关。

## 1.6.18：启动时直接优化 info 文件

不再生成或读取独立的 LZ4 资源缓存。每次启动先检查各地图顶层 `info*`：已是独立 LZ4／未压缩分块的包直接跳过；支持的单块 LZMA 包在后台串行转为 LZ4，核对文件哈希、完整解压数据哈希、CAB／节点目录和版本后，原子替换原路径。后续关卡扫描、预览、单机／房主／客机和原 MOD 直接读取的都是同一个优化后文件。

原件保存在对应地图的 `.diylevel-fastinit/original-<GUID>.bundle`，配套 `.record` 记录原文件名及转换前后哈希。备份和临时文件均位于子目录，不会混入顶层 `info*` 扫描。文件被占用、权限不足、校验失败或格式不支持时保留原件并记录原因，下次启动可重试。替换提交期间保留完整备份；取消不会把文件截断或写成半成品。

配置位于 `BepInEx/config/oc2.diylevel.fastinit.cfg`：

- `Loading.OptimizeInfoBundlesOnStartup=true`：默认开启，每次启动自动检查；关闭只停止后续转换，不会还原已经替换的文件。
- `Loading.RestoreOriginalInfoBundlesOnStartup=false`：需要恢复时改成 `true` 并重启，恢复操作优先。仅在当前文件和备份均匹配记录哈希时恢复，地图后来更新过则不覆盖。恢复后将此项设回 `false`；如需继续保留 LZMA，同时关闭自动优化。
- 旧 `EnableLz4BundleCache`、`Lz4BundleCacheSizeMiB` 选项不再生效；目录标量缓存和缩略图缓存继续工作。

首次转换会延长启动等待，界面显示 `DIY info checking ...`。转换和目录扫描完成前不允许原生 info 加载；提前收到的联机进图消息先保留并回复开始加载，再等待目录就绪，不提前宣布厨房就绪。以后启动跳过已优化文件。首次替换会使基于文件指纹的目录／缩略图缓存重建一次；备份会增加磁盘占用。

日志 `info bundle optimized in place` 表示替换成功，`info bundle startup optimization complete` 显示替换／跳过／失败统计；后续 `info bundle source: ... (source file)` 表示正在读取地图原路径，其内容已可为 LZ4。

## 1.6.17 的优化与界面修复

将 1.6.16 的 LZ4 缓存扩展到所有兼容的 DIY `info*` 包，不再限定 DMM。保留格式版本 2，已有的有效 DMM 缓存可以继续复用。当前安装的 20 个 info 包全部支持；不支持的格式在本次进程内记住并回退原件，小场景包、`common*` 和七池运行库持有的独立资源包仍由原加载器处理。

缓存预算默认提高到 2 GiB，可通过 `Loading.Lz4BundleCacheSizeMiB` 调整（128–16384 MiB，重启生效）。本机 20 包转换后共 575.27 MiB，旧的 512 MiB 上限无法同时容纳。后台先校验已有缓存，再转换未命中的包；扫描排队不会刷新已有条目的最近使用时间或占用文件租约。仍需在前端空闲时等待生成／校验，未就绪时立即使用原件。

修复确认存档后选档框提前消失的问题：在确认回调开始时保留选档框，并使用 Team17 的事件系统 suppressor 锁住输入；存档读写和界面 Update 继续运行。准备资源期间只等待存档例程完成，不提前 `Hide(false)`；真正切图后释放自己的输入锁。覆盖“不保存”路径，并在取消、失败、断线或改选官方关卡时释放当前请求的界面锁，旧请求的收尾不会释放新请求的锁。

## 1.6.16 的修复

修复已生成 LZ4 缓存却仍使用原文件的问题。1.6.13–1.6.15 把原始 LZMA 数据块的 `Streamed=0x40` 标记沿用到独立 LZ4／未压缩分块，游戏原生读取器因此调用不支持的 LZ4 流式解压路径，报 `Failed to decompress data for the AssetBundle` 并写下 `.bad`，后续一直回退原文件。现在新分块只写压缩类型 `0x02`／`0x00`，保留其余压缩字节和资源内容。

缓存键增加格式版本 2；旧缓存和旧拒绝标记会自动隔离，不必手动删除。升级后留在空闲主菜单等待新缓存生成，日志应先有 `bundle file cache built`，实际进入 DMM 时再确认 `info bundle source: info_dmm (LZ4 cache)`。启动日志会显示 `format 2`；若新缓存曾被 Unity 拒绝，后续也会明确记录禁用原因。

本机 1.6.15 的实际现场是原文件读包 7,597 毫秒、单关信息 78 毫秒、准备合计 7,926 毫秒、从交给原切图流程到场景就绪另 3,566 毫秒。该次没有命中 LZ4，不能据此测量缓存收益。原生拒绝、持久标记和分阶段耗时证据保存在 `../.verification/perf-1.6.15/`。

## 1.6.15 的修复

修复 1.6.13／1.6.14 在游戏自带 Mono 上无法首次生成 LZ4 缓存的问题：该运行库对缺失文件／路径可能抛出 `IsolatedStorageException`，它不继承 `IOException`。原实现检查不存在的 `.bad`／`.meta` 时中断任务，目录里仅留下 `.lock`。转码器的源读取还使用了该运行库缺失的 `FileOptions` 构造函数重载，现改用实际支持的五参数重载。现在缺失文件正常视为未命中，同时处理检查后文件消失的竞态；错误日志保留异常类型和堆栈，启动时记录缓存启用状态与实际目录。

缓存位置是 `BepInEx/cache/DIYLevelFastInit/bundles/`，完成后为哈希文件名的 `.bundle` 和 `.meta`，不是 `.lz4` 扩展名。1.6.15 仅转换支持的 `info_dmm`；1.6.17 已扩展到所有兼容的 `info*`。保持 `Loading.EnableLz4BundleCache=true`，目录扫描／缩略图源加载结束后留在空闲前端即可生成；进图或游玩会暂停转换。日志 `bundle file cache built` 表示生成完成，后续 `info bundle source: info_dmm (LZ4 cache)` 表示本次加载使用了缓存。已有 `.lock` 不必删除。

## 1.6.14 的优化

进图、未缓存预览和缩略图预热改为直接请求选中的 `LevelInfoSO` 资源。完整轻量目录、原有顺序和 SO 身份保持稳定。每个已加载的关卡集建立资源文件名索引，只有目录对象名称唯一匹配时才使用该地址，并校验返回对象的类型、名称和场景；缺失、歧义或无效地址回退到完整 `LevelSetInfo`。同目标请求共享，不同关卡分别等待。取消后先等待原生请求结束，不会继续为旧目标启动回退。

支持直接地址的地图，预热每关后释放源引用并等待安全回收；旧包全量回退时，同批继续复用全关卡集，避免反复加载。切换同集关卡会清理不用的单关引用，保留活动／待加载场景以及当前未缓存预览所需依赖。配置中将 `Loading.EnableIndividualLevelAssets=false` 后重启可恢复全量资源加载。首次目录扫描在标量缓存未命中时仍需读取 `LevelSetInfo`。下述 LZ4 缓存可独立启用。

## 1.6.13 的优化

为安装中的 `info_dmm` 格式增加可丢弃的 LZ4 文件缓存。未命中时立即加载原文件并排队转换；单个低优先级托管线程只在前台加载和游戏空闲时工作，不覆盖地图原件。每个进程首次使用缓存前在后台验证源文件和输出的 SHA-256，完成后发布已校验的元数据，已发布数据上限为 512 MiB。Unity 原生请求和已加载容器会持续占用缓存文件，直到请求完成／容器卸载。Unity 拒绝缓存时回退原文件，并禁用该源指纹对应的缓存。

缓存位于 `BepInEx/cache/DIYLevelFastInit/bundles/`。配置中将 `Loading.EnableLz4BundleCache=false` 后重启可禁用；关闭游戏后可直接删除缓存。1.6.13 当时仅转换支持的单块 LZMA `info_dmm`；1.6.17 已扩展到兼容的 `info*`，小场景包仍保持原加载方式。转换采用有界流式缓冲，保留节点目录、CAB 名称与解压后的资源字节。转换或校验尚未完成时，本次进图仍可能使用原件。暂停中的转换会保留源文件读句柄，直到继续或退出；期间 Windows 可能阻止覆盖该源文件。1.6.13 负责文件解压优化；1.6.14 另加入上述对象加载范围优化。

保留 1.6.12 的取消和选档同步修复：

本版依据 Team17 按连接处理加载与就绪状态的方式，修复取消、重连和切换选档时的状态残留：

- 客机取消准备后，立即停止用旧请求拦截选档就绪回执；旧的原生资源请求仍安全等待完成。成功交给原加载流程后，拦截仅对原邮箱、peer 和连接生效，并在目标场景到达时结束。
- 房主准备过程在等待后及切图交接前检查请求代次和网络上下文。返回前端、连接重置或角色改变会使旧请求失效，避免取消后又以离线身份进入旧关卡。
- 从已确认的 DIY 选档切换到官方 DLC 选档时，立即清除上一轮确认并撤销旧进图权限，避免房主等待选档回执、客机等待下一条切图消息的互相等待。官方倒计时和后续新的 DIY 选档可在旧资源请求安全结束期间正常进行。

保留 1.6.11 的源码结构。资源请求完成前仍保留必要引用；关卡就绪仍由原始厨房加载状态机通知。

此前的异步加载消除了主菜单的长时间冻结，但全部 `info_*` 资源和所有关卡的四套人数配置仍然常驻。对于 32 位游戏，启动快并不等于内存占用低。

现在保留完整的轻量关卡目录，配方、音乐、截图等资源按需加载：

- **启动扫描**：先准备 `common*`，再逐个异步读取关卡集的 `info_*`。复制名称、UID、场景名、依赖名称及人数设置后，使用 `Unload(false)` 关闭包；清除临时完整信息引用后，在前端等待 Unity 回收无引用资源，再继续扫描。不再同时排队全部 info 包。
- **磁盘目录缓存**：缓存写入 `BepInEx/cache/DIYLevelFastInit/`，采用带版本号、长度上限和完整性检查的二进制格式，只包含字符串与数值，不依赖 Unity 的 JSON 序列化器。下次启动按路径、info 文件名、长度及修改时间校验，命中时无需加载对应 info 包。缓存损坏或无法写入时回退到扫描；可在游戏关闭后删除缓存以强制重建。
- **轻量场景目录**：保留全部关卡及原有位置映射，供菜单、街机和存档使用；打开存档选择界面不再生成全量配方配置。
- **目标关卡配置**：单机／房主确认存档后先让出一帧，异步读取目标关卡的 info 资源，再分帧准备该关卡的四套人数配置，显示准备进度；就绪后只继续一次原来的服务器加载流程，准备中合并重复请求。其他关卡不预热，重开同关可复用目录配置。远端客机在客户端邮箱分发进图消息之前，复制目标场景、加载状态和加载画面参数，异步准备资源并逐帧生成四套配置；就绪后只恢复一次原来的消息分发。等待期间继续处理其他网络消息，并显示 `client` 准备进度。原来的 `LoadLevelClientPatch` 保留同步时序，恢复时使用已经准备好的资源。重复进图请求合并；改选关卡、返回其他场景、断线或重连时，旧请求失效，正在进行的原生资源请求完成后再释放资源。
- **加载优先级**：单机／房主确认进入关卡、已有缩略图和目录请求结束后，临时把 Unity 后台加载优先级提高到 `High`，覆盖资源准备及目标场景加载；目标关卡或前端场景就绪、准备失败、插件销毁时恢复之前的值。如果其他加载器已改成不同的值，则保留其修改。加载期间可能牺牲帧率以缩短等待，并分别记录资源包加载与 info 资源实例化耗时；加载状态同步顺序保持不变。
- **跨关卡集依赖**：读取场景和 info 的资源引用元数据，递归加载它们实际依赖的其他 info 包，修复只加载自身 info 时跨关卡集材质丢失的问题。依赖包只打开容器，不额外读取其 `LevelSetInfo` 或生成关卡配置；共享依赖保留到最后一个使用者退出。只读元数据解析内置在 DLL 中，无需 Python 或额外插件。
- **七池独立资源**：读取 `info_qichi` 前，先通过已安装的七池运行库（v10 接口）准备独立的 `qichi_assets`。等待已有异步请求，或复用已加载的包，并同步运行库的完成状态，避免反复重复加载。冷扫描、源图预览和单机／房主、客户端进图均覆盖；资源包仍由七池运行库持有，FastInit 不卸载。缺少运行库时记录提示；已安装的加载器接口不兼容或请求失败时，中止本次资源准备。
- **资源回收**：按场景是否仍在使用决定何时释放 info、配置和运行时 prefab。info 包解除引用并 `Unload(false)` 后，合并清理请求，在前端由 `Resources.UnloadUnusedAssets()` 回收无引用对象，保留仍被使用的材质和 Shader；不在 DIY 关卡或切图中主动启动这项清理。切图允许新旧资源短暂重叠；每次重开产生的场景运行时对象按场景实例回收。
- **提前生成缩略图**：内置对 OC2StageThumbnailPreview 1.0.0 的适配。目录加载完成后，自动逐个关卡集提前生成小图，写入 `BepInEx/cache/DIYLevelFastInit/thumbnails/`，无需先逐张浏览；屏幕显示缓存进度。支持直接地址时每关完成即释放源资源并等待回收，旧包全量回退按批次回收。之后浏览直接读取硬盘上的小图，最大 640 × 360；内存最多保留最近 8 张，进入关卡时清空，硬盘最多 128 MiB，超限淘汰最旧条目。按 info/common 源文件指纹判断过期，校验图片尺寸、长度和校验和。后台生成会为游戏、切图和未缓存的前台预览暂停；已缓存的图片可直接读取，无需等待正在进行的预生成。缺失或无效缓存回退到异步读取源包。快速切换只显示最新选中的图片；排序插件仍使用原有的轻量 SO 对象。
- **选档与加载衔接**：拦截同帧重复选关、已打开或切图期间的重复选档请求，以及重复的存档确认。完成选择（含“不保存”）后记住本轮结果并停止客机选档倒计时；重复收到房主请求时复用已选存档并补发就绪回执，进入加载后不再补发旧选档状态。单机／房主与客机确认存档后保留选档框并锁住输入；只隐藏等待覆盖层，不提前关闭选档框。若存档读写仍在处理，每帧等待其完成，继续运行其 Update。切图后释放自己的输入锁，取消或失败按请求身份恢复界面。客机先回复“开始加载”，资源就绪后只恢复一次切图消息；“关卡已就绪”仍由原始场景流程通知。新选关、连接重置和场景到达清除本轮选择记录。只作用于 DIY DLC 15；确认前取消仍可重新选择。
- **热刷新**：保留“刷新关卡列表”，只更新有变化的目录；正在切图或关卡内不刷新。刷新过程中禁止选关。
- **异步请求**：15 秒未完成时记录等待提示，继续等待同一个请求；仅在请求已经完成且失败后同步重试，避免无法取消的旧请求与新请求争抢同一个包。

原版共享依赖仍由原版管理器及其引用计数管理。本补丁会备份并替换上述 info 文件；不强制清空公共包，不修改游戏 EXE、场景包、原 mod DLL 或存档格式。

## 边界

仍需打开目标场景／关卡集的 info 容器及关联 info 依赖；容器内有独立地址时，只请求选中关卡的对象图。这不等于拆分文件，也不会移除该关卡本身引用的资源。使用原始 LZMA 文件仍可能需要整块解压，不支持独立地址的包仍全量回退。`common*` 以及其他 MOD 的常驻资源不在本补丁回收范围内。

第一次扫描、预生成缩略图，以及第一次进入关卡，仍有读取、解压和配置生成成本。预生成期间会暂时加载源 info 资源，每帧最多生成一张图片，独立关卡或全量回退批次之间等待无引用资源回收；尚未缓存的图片仍可能较慢显示。未安装缩略图插件时跳过预生成。单机／房主与正常联机客机准备期间异步等待资源加载，但每套配置仍在主线程生成，单套复杂配置或 Unity 场景激活仍可能造成个别慢帧。客机门控针对原版可靠的 `LevelLoadByName` 消息；直接调用原插件客户端准备方法的其他 MOD 仍走同步兜底。等待初始目录加载完成后再使用完整关卡列表和联机。

七池适配调用运行库自身的读文件和解码流程，启动请求时仍可能产生慢帧；仅覆盖已核对的 `info_qichi` 布局，不会自动发现其他 MOD 的任意独立资源包。冷启动后的七池背景显示仍需实机验证。

## 安装与回退

关闭游戏，备份已安装的 `BepInEx/plugins/DIYLevelFastInit.dll`，再用新 DLL 替换。回退插件时关闭游戏并恢复 DLL 备份；已经优化的 info 文件仍可直接加载，需要还原原件时先使用上述恢复配置。目录缓存可保留，也可删除。不要让两个版本的 DLL 同时出现在 plugins 扫描范围内。

```powershell
dotnet build -c Release -p:GameDir="D:\Games\Steam Games\steamapps\common\Overcooked! 2"
```

## 源码结构

| 位置 | 职责 |
| --- | --- |
| `FastInitPlugin.cs`、`Plugin/` | 插件生命周期、公共初始化、加载进度显示 |
| `Catalog/` | 轻量元数据、目录及缓存、发现和热刷新 |
| `Frontend/` | 菜单、选档、已确认存档的复用 |

`FastInitPlugin` 和 `OnDemandResources` 通过 `partial` 拆分，保留原来的类型名与补丁方法名。共享字段及初始化器集中留在各自的核心文件内，保持原始顺序。项目使用 SDK 默认源码包含规则，仍然只生成一个插件 DLL。

查看 `BepInEx/LogOutput.log` 中的 `DIYLevel FastInit`：

- `level set [...] ready (... metadata only)`：扫描完成后只保留目录。
- `catalog cache hit: ...`：重启命中磁盘缓存。
- `lightweight scene directory: ... no recipe configs`：存档界面未全量生成配置。
- `on-demand info loaded/released`：当前跟踪的包数量，不能据此推断所有旧资源已立即回收。
- `info dependency graph`、`info dependency released`：目标场景需要的 info 包及共享依赖的释放。
- `Qichi dependency loading` / `Qichi dependency ready`：七池独立背景资源；新进程中应先就绪，再出现 `on-demand info loaded` 和七池场景加载，且不应持续报告重复的 `Memory` 包。
- `on-demand preview info loaded`、`thumbnail ready (... async ... ms elapsed)`：异步预览完成；耗时包含该次加载的异步等待时间，不代表主线程冻结时间。
- `thumbnail prewarm complete: ... disk entries ready`：提前生成的磁盘条目数量；`thumbnail cache hit: ... (disk|memory, ... ms)`：浏览命中缓存，没有读取源 info。
- `on-demand config ready/released`、`scene runtime objects released`：目标配置与每次场景实例的回收。
- `async level preparation started`、`async level resources ready`、`on-demand config ready (... async level entry ...)`：单机／房主异步准备；总耗时包含异步等待，单套配置耗时超过或等于 50 毫秒时还会输出 Info 计时。
- `DIY client level message deferred/resumed`、`async client level preparation started`、`client level bundle ready`、`client level info asset ready`：客机异步准备及一次恢复；`DIY client level preparation cancelled`：旧连接或旧目标失效。
- `duplicate DIY ... ignored`：重复选关、选档或存档确认被拦截。
- `DIY save dialog opened/closed`、`DIY save choice confirmed`、`DIY server save acknowledgement received`、`DIY server/client save UI retained with input locked during resource preparation`：选档弹出、关闭、确认、房主收到回执，以及加载前界面保留／输入锁定。房主回执列出各机器／槽位的游戏状态，不记录账号 ID。`DIY client loading acknowledged before resources`、`DIY client state sent`：开始加载的衔接；`DIY client disconnect path`：客机开始加载后两分钟内的断线调用路径，只记录，不改变断线处理。`Qichi runtime request startup`：七池原生异步等待之前，同步启动请求（含运行库读文件／解码）的耗时。
- `level loading priority`、`level loading priority released`：临时提高与释放加载优先级；`level bundle ready`、`level info asset ready`：分阶段计时。优先级释放日志还会记录交给原始切图流程后的耗时。
- `scene material audit`、`scene material invalid`：进入 DIY 场景后对材质 Shader 引用与支持状态做一次只读检查；不会自动替换材质。

回归检查应覆盖：浏览和排序、缩略图、存档选择与读写、进入关卡、连续重开、跨关卡集切图、返回菜单、热刷新，以及房主和客户端联机。记录游戏进程的专用内存；场景切换有暂时峰值，不能仅凭一次读数判断泄漏。1.6.11 已通过离线消息所有权、一次恢复、开始加载回执提前且不重复、旧选档状态拦截、原始关卡就绪信号保留、取消、发送失败和重连检查；另验证了已确认选择的复用、跨前端／重置隔离，以及存档忙时逐帧等待关闭。31 个补丁签名及选档字段／方法均与已安装程序集核对通过。源码拆分还逐项比对了 23 个顶层类型、410 个成员的声明和方法体，以及属性标记、基类和字段顺序；仅允许 `partial` 声明及版本常量变化。1.6.9 的 DMM 联机已有可进入反馈；后续原生界面及双方联机仍需回归。七池客机退出尚未定位，需要出问题的客机日志，不能据此承诺已修复。
